# CAILLOU™ - Étape 10.75 - Boutique unifiée et manipulation universelle

> **Statut : À faire**  
> **Position dans la roadmap : après 10.5, avant 11**  
> **Nature : consolidation UX/UI, factorisation tactile et clarification du parcours commercial**  
> **Dépendances : 10B, 10C, 10D, 10.5**  
> **Principe directeur : Boutique = acquérir. Placement = manipuler. Rapier = arbitrer après validation.**

---

## 1. Contexte

L'étape 10.5 a livré un vrai sol physique, la manipulation tactile 6D du caillou, le Permis de manutention minérale à 1000 Lithons et la stabilisation atomique caillou + accessoires.

Les essais UX qui ont suivi ont montré une différence nette entre deux grammaires d'interaction :

- la manutention du caillou utilise tout le canvas comme surface de contrôle, avec des sous-modes Position et Orientation simples ;
- le placement des accessoires dépend encore d'une prise directe sur le petit objet et d'une projection vers une surface de la scène.

Le contrôleur du caillou est retenu comme référence ergonomique pour la suite.

Par ailleurs, deux responsabilités sont encore mélangées dans l'interface actuelle :

- la boutique sert à acheter mais aussi à créer une instance placée ;
- deux boutons distincts existent pour modifier les accessoires et déplacer le caillou.

L'étape 10.75 doit unifier ces parcours sans modifier l'économie fondamentale ni réécrire l'historique des étapes 10A à 10.5.

---

## 2. Objectif fonctionnel

À la fin de 10.75, l'utilisateur doit comprendre deux règles seulement :

```text
Je veux acquérir quelque chose -> Boutique
Je veux déplacer quelque chose -> Placement
```

Le Socle doit proposer :

- une Boutique commerciale unique ;
- un bouton Placement unique ;
- un sélecteur de cible commun au caillou et aux accessoires ;
- une grammaire tactile commune ;
- une manipulation libre dans l'espace ;
- le carré gris comme seule frontière infranchissable pendant le placement ;
- la reprise complète de la gravité et des collisions Rapier après validation.

---

## 3. 10.75-A - Boutique commerciale unifiée

### 3.1 Une seule fenêtre d'achat

L'actuelle boutique d'accessoires devient la Boutique générale du Socle.

Elle agrège au minimum deux familles de produits :

1. **Accessoires** ;
2. **Autorisations / services**.

Le premier produit de la seconde famille est :

```text
Permis de manutention minérale
Prix serveur : 1000 Lithons
Propriété : permanente au compte
```

### 3.2 Backend conservé spécialisé

L'unification est une responsabilité de présentation frontend.

Les modèles Supabase restent spécialisés :

```text
accessories
user_accessories

feature_catalog
user_feature_unlocks
```

Les achats restent servis par leurs RPC autoritaires existants :

```text
purchase_accessory(accessory_id, event_key)
purchase_feature_unlock(feature_id, event_key)
```

Il ne faut pas fusionner artificiellement les tables SQL uniquement pour afficher les produits dans la même fenêtre.

### 3.3 États commerciaux

Une carte de produit doit pouvoir afficher clairement :

- nom ;
- description ;
- prix en Lithons ;
- disponibilité ;
- état `Acquis` / `Possédé` ;
- insuffisance de solde ;
- confirmation en cours ;
- erreur retryable avec conservation du même `event_key`.

Le Permis de manutention minérale déjà acquis ne peut pas être acheté une seconde fois.

### 3.4 Suppression du parcours commercial parallèle

Le composant de dialogue dédié à l'achat du permis n'est plus la destination commerciale cible.

Lorsqu'un utilisateur sans permis demande la manutention du caillou, l'interface doit le diriger vers la fiche du permis dans la Boutique unifiée.

---

## 4. 10.75-B - Séparation stricte Achat / Placement

### 4.1 Boutique

La Boutique :

- consulte le catalogue ;
- réalise les acquisitions ;
- met à jour le solde confirmé ;
- n'est pas l'endroit où l'utilisateur déplace des objets.

### 4.2 Placement

Le mode Placement :

- sélectionne une cible ;
- crée une nouvelle instance d'un accessoire déjà possédé si demandé ;
- déplace / oriente / redimensionne la cible selon ses capacités ;
- lance la stabilisation physique à `Terminer` ;
- persiste uniquement un état final confirmé.

### 4.3 Multi-instance

La propriété d'un type d'accessoire reste distincte de ses instances équipées.

Après acquisition d'un type, l'utilisateur peut créer plusieurs instances depuis Placement sans retourner dans la Boutique.

Le plafond V1 reste :

```text
8 instances équipées maximum par caillou
```

Aucune nouvelle exclusivité par `slot` n'est introduite.

---

## 5. 10.75-C - Bouton Placement unique

### 5.1 Une seule entrée de manipulation

Les contrôles séparés « modifier les accessoires » et « manutention du caillou » doivent converger vers un seul bouton **Placement** dans la zone utilitaire du Socle.

Ce bouton ne réalise aucun achat directement.

### 5.2 Sélecteur de cible

À l'ouverture, l'utilisateur choisit ce qu'il souhaite manipuler.

Exemple conceptuel :

```text
PLACEMENT

Caillou
  Bernard

Accessoires placés
  Lunettes rondes #1
  Monocle #1
  Lunettes rondes #2

+ Ajouter un objet possédé
```

La liste doit identifier les instances sans ambiguïté lorsque plusieurs exemplaires du même type sont présents.

### 5.3 Caillou sans permis

Le caillou reste visible dans le sélecteur même si le compte ne possède pas le Permis de manutention minérale.

Son état devient verrouillé et explique la condition manquante.

L'action associée doit conduire vers la fiche du permis dans la Boutique unifiée au lieu d'ouvrir un second circuit d'achat.

### 5.4 Modes exclusifs

Placement reste mutuellement exclusif avec :

- Orbit / observation ;
- Caresser ;
- Nettoyer ;
- stabilisation physique ;
- les mutations bloquantes.

---

## 6. 10.75-D - Moteur tactile commun

### 6.1 Référence ergonomique

Le contrôleur de manutention du caillou livré en 10.5 devient la référence pour toutes les cibles manipulables.

Une fois la cible choisie, **le canvas entier devient la surface de contrôle**.

Il ne faut plus imposer à l'utilisateur de maintenir précisément son doigt sur un petit mesh d'accessoire pendant toute la manipulation.

### 6.2 Position

Pour le caillou et les accessoires :

- **1 doigt** : translation dans le plan de vue ;
- **2 doigts** : translation en profondeur.

### 6.3 Orientation

Pour le caillou et les accessoires :

- **1 doigt** : orientation libre de type trackball / axes caméra ;
- **twist à deux doigts** : rotation complémentaire autour de l'axe de vue.

### 6.4 Taille

La taille est disponible uniquement lorsque la cible le permet.

Pour les accessoires :

- **pinch** : échelle uniforme ;
- respect de `scale_min` et `scale_max` du catalogue.

Le caillou ne change pas d'échelle.

### 6.5 Réglage fin

Les contrôles numériques / X-Y-Z peuvent rester accessibles comme réglage secondaire replié.

Ils ne doivent pas redevenir la méthode principale de manipulation.

### 6.6 Architecture cible

La logique doit tendre vers un contrôleur générique, par exemple conceptuellement :

```text
ManipulationController
  target: rock | accessory-instance
  capabilities:
    position: true
    rotation: true
    scale: false | true
```

Le contrôleur reçoit une cible et des capacités. Il ne doit pas contenir deux grammaires tactiles concurrentes selon la nature de l'objet.

## 7. 10.75-E - Liberté de placement et frontière du sol

### 7.1 Liberté volontaire

Pendant une session Placement, la main de l'utilisateur est autoritaire sur la cible.

Il ne faut appliquer **aucune contrainte de collision** avec :

- le caillou ;
- les autres accessoires ;
- les accessoires entre eux.

L'utilisateur peut volontairement :

- faire pénétrer un accessoire dans le caillou ;
- imbriquer plusieurs accessoires ;
- placer une cible dans une position physiquement incohérente ;
- laisser une cible suspendue avant validation.

Le placement ne doit pas tenter de corriger, repousser, aimanter ou projeter automatiquement la cible vers une surface du caillou.

### 7.2 Exception unique : le carré gris

Le grand carré gris du Socle est la seule frontière infranchissable pendant la manipulation cinématique.

Aucune cible manipulée, caillou ou accessoire, ne doit pouvoir être déplacée manuellement à travers ou sous ce sol.

Cette règle doit être appliquée comme **contrainte dure de position pendant le geste**, et non laissée uniquement à une collision Rapier après coup.

La contrainte doit tenir compte du volume / de l'enveloppe de la cible afin d'empêcher son corps de traverser visiblement le plan du sol.

### 7.3 Règle résumée

```text
Pendant Placement :
main utilisateur > collisions caillou/accessoires
sol gris > main utilisateur

Après Terminer :
Rapier > composition complète
```

### 7.4 Retour de Rapier

Au clic sur **Terminer** :

- la cible cesse d'être pilotée cinématiquement ;
- la gravité reprend ;
- les collisions normales redeviennent actives ;
- Rapier résout les pénétrations créées volontairement pendant le placement ;
- une éjection rapide ou spectaculaire due à une forte intersection est un résultat physique acceptable ;
- aucune animation cartoon artificielle ne doit être ajoutée pour accentuer cet effet.

---

## 8. 10.75-F - Stabilisation et persistance

### 8.1 Accessoire seul

Après validation d'un accessoire :

```text
brouillon cinématique
  -> Terminer
  -> corps dynamique
  -> gravité + collisions
  -> sommeil / timeout
  -> conversion monde vers repère local du caillou
  -> stabilize_equipped_accessory(..., event_key)
  -> état canonique Supabase
```

### 8.2 Caillou

La manutention du caillou conserve le contrat 10.5 :

```text
caillou manipulé + accessoires gelés
  -> Terminer
  -> caillou + accessoires dynamiques ensemble
  -> stabilisation globale
  -> stabilize_rock_composition(..., event_key)
  -> pose du caillou + transforms locaux accessoires persistés atomiquement
```

### 8.3 Intentions d'intersection

Les validations serveur doivent protéger :

- propriété ;
- identité des instances ;
- bornes numériques ;
- quaternion valide ;
- limites d'échelle ;
- enveloppe générale empêchant la perte d'une cible hors scène ;
- autorisation de manutention du caillou.

Elles ne doivent pas introduire une règle métier interdisant les intersections volontaires entre objets pendant le placement.

### 8.4 Migration Supabase

Hypothèse initiale : **aucune migration de schéma n'est nécessaire** pour 10.75.

Le modèle actuel possède déjà :

- les deux catalogues commerciaux spécialisés ;
- les possessions accessoires ;
- les déblocages de fonctionnalités ;
- les instances équipées ;
- la pose persistante du caillou ;
- les transforms locaux des accessoires ;
- la stabilisation individuelle ;
- la stabilisation atomique de composition.

Une migration n'est ajoutée que si l'inspection d'exécution démontre un besoin réel.

## 9. 10.75-G - QA tactile et non-régression

### 9.1 Parcours téléphone et tablette

La validation navigateur dédiée doit couvrir au minimum :

- ouverture du Placement ;
- sélection du caillou ;
- caillou verrouillé sans permis ;
- redirection vers le permis dans la Boutique ;
- achat du permis depuis la Boutique ;
- sélection d'une instance accessoire ;
- sélection de plusieurs instances distinctes ;
- création d'une nouvelle instance depuis un type déjà possédé ;
- Position X/Y/profondeur ;
- Orientation ;
- Taille accessoire ;
- canvas entier utilisable comme surface de geste ;
- intersection volontaire accessoire / caillou ;
- intersection volontaire accessoire / accessoire ;
- impossibilité de traverser le carré gris ;
- libération Rapier après forte intersection ;
- stabilisation puis reload ;
- conservation des transforms et identités d'instances.

### 9.2 Non-régression

Les scénarios historiques restent verts :

- showroom ;
- adoption ;
- caresse ;
- nettoyage ;
- boutique / économie ;
- multi-accessoires ;
- physique accessoires ;
- manutention du caillou ;
- composition atomique.

### 9.3 Vercel

La discipline de quota reste obligatoire :

- privilégier GitHub CI et validations locales/navigateur pendant l'itération ;
- déclencher une Preview Vercel volontaire uniquement sur le candidat final utile ;
- ne pas multiplier les déploiements de validation ;
- après fusion, vérifier le déploiement Production correspondant au SHA fusionné.

## 10. Critères d'acceptation

- [ ] une seule Boutique centralise les achats ;
- [ ] les accessoires et fonctionnalités payantes restent des modèles backend spécialisés ;
- [ ] le Permis de manutention minérale est achetable dans la Boutique pour exactement 1000 Lithons ;
- [ ] le dialogue commercial autonome du permis n'est plus nécessaire au parcours cible ;
- [ ] la Boutique n'est plus le point d'entrée principal pour placer une instance déjà possédée ;
- [ ] un seul bouton Placement mutualise caillou et accessoires ;
- [ ] le sélecteur distingue clairement le caillou et chaque instance accessoire ;
- [ ] un accessoire possédé peut créer une nouvelle instance depuis Placement ;
- [ ] le caillou sans permis reste visible mais verrouillé ;
- [ ] caillou et accessoires partagent la même grammaire Position / Orientation ;
- [ ] les accessoires ajoutent le contrôle de Taille ;
- [ ] le canvas entier sert de surface de manipulation après sélection ;
- [ ] les intersections avec caillou et accessoires sont autorisées pendant Placement ;
- [ ] aucun snapping / anti-pénétration n'empêche le placement fin volontaire ;
- [ ] le carré gris est infranchissable pendant toute manipulation cinématique ;
- [ ] à Terminer, Rapier reprend gravité et collisions normales ;
- [ ] une résolution physique énergique d'une intersection volontaire est acceptée ;
- [ ] la stabilisation individuelle accessoire reste persistante ;
- [ ] la stabilisation globale caillou + accessoires reste atomique et idempotente ;
- [ ] téléphone et tablette sont couverts ;
- [ ] les parcours historiques restent verts ;
- [ ] aucune régression RLS ou économique ;
- [ ] Vercel n'est utilisé volontairement qu'au moment utile.

---

## 11. Hors périmètre

10.75 ne doit pas être utilisé pour :

- créer une nouvelle monnaie ;
- modifier la règle `1 caresse valide = 1 Lithon` ;
- vendre des Lithons contre de l'argent réel ;
- fusionner artificiellement les catalogues SQL ;
- ajouter une simulation physique serveur ;
- interdire les intersections volontaires par une nouvelle règle métier ;
- refaire le pipeline 3D des cailloux ou des accessoires sans défaut démontré ;
- augmenter la limite de huit instances sans décision explicite ;
- réécrire l'historique des étapes 10A à 10.5 ;
- commencer l'étape 11.
