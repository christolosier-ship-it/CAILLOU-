# CAILLOU™ - Étape 10.5 - UX tactile, sol physique et manutention du caillou

> **Statut : Implémentée et validée côté GitHub / Supabase, candidate à la validation Vercel finale**  
> **Position dans la roadmap : après 10D, avant 11**  
> **Nature : consolidation UX + extension physique + déblocage économique premium**  
> **PR d'exécution : #25 - `feat: exécuter l’étape 10.5 tactile et manutention`**  
> **Principe : rien ne doit pouvoir être déplacé accidentellement ; quand l'utilisateur choisit de manipuler la scène, le tactile doit être naturel et Rapier redevient l'arbitre final.**

---

## 1. Contexte

Les étapes 10A à 10D avaient livré :

- le pipeline et le catalogue d'accessoires 3D ;
- la boutique et la propriété permanente ;
- le multi-équipement et les transforms persistants ;
- Rapier, la gravité, les collisions et la stabilisation persistante des accessoires.

Les premiers essais d'usage avaient ensuite mis en évidence trois limites :

1. le placement des accessoires reposait encore trop sur des commandes techniques X/Y/Z ;
2. la gravité reprenait trop tôt pendant l'édition ;
3. toucher un accessoire pouvait trop facilement l'amener dans un état éditable.

Une quatrième évolution a été ajoutée au même jalon : permettre à l'utilisateur de déplacer physiquement son caillou, après achat d'un déblocage permanent très coûteux en Lithons.

Cette étape 10.5 est une évolution postérieure à 10D. Elle ne réécrit pas l'historique des étapes 10A à 10D.

---

## 2. Résultat fonctionnel livré

### 2.1 Verrouillage explicite de l'édition des accessoires

Le Socle dispose désormais d'un mode d'édition accessoire explicitement activé dans la barre supérieure.

Hors de ce mode :

- les accessoires restent visibles mais ne sont pas transformables ;
- un toucher sur un accessoire ne bascule plus implicitement l'application en édition ;
- la caméra conserve son fonctionnement normal ;
- les autres modes restent mutuellement exclusifs.

Le bouton Accessoire historique conserve son rôle de boutique / ajout. Le contrôle supérieur sert à modifier les accessoires déjà placés.

### 2.2 Manipulation tactile directe des accessoires

L'édition est devenue tactile-first :

- **1 doigt** : déplacement direct vers la surface visée ;
- **twist à deux doigts** : rotation ;
- **pinch** : changement d'échelle dans les bornes du catalogue.

Le placement direct utilise les surfaces réelles de la scène au lieu d'un simple plan parallèle à la caméra.

Les commandes X/Y/Z sont conservées comme **Réglage fin** secondaire, replié dans l'interface.

### 2.3 Gravité gelée pendant toute la session d'édition

Pendant l'édition d'un accessoire :

- l'objet reste cinématique ;
- la gravité ne reprend pas entre deux gestes ;
- le brouillon tactile reste côté client pendant la session ;
- la validation déclenche seulement ensuite la résolution physique.

Cycle livré :

```text
activer édition
  -> sélectionner accessoire
  -> manipulation cinématique sans gravité
  -> valider
  -> libération dynamique
  -> gravité + collisions
  -> sommeil / timeout de sécurité
  -> persistance finale
```

### 2.4 Le grand carré est le vrai sol physique

Le grand carré visible sous le caillou possède désormais un collider Rapier fixe partageant les mêmes constantes de position et de dimensions que le rendu de référence.

Conséquences :

- un accessoire qui rate le caillou tombe sur ce sol ;
- un caillou libéré après manutention retombe sur ce sol ;
- la physique ne possède plus un sol implicite différent du repère visuel.

## 3. Permis de manutention minérale

### 3.1 Prix et propriété

Le droit de déplacer le caillou est commercialisé en Lithons sous la forme d'un déblocage permanent :

```text
Permis de manutention minérale = 1000 Lithons
```

Décisions effectivement implémentées :

- prix autoritaire serveur : **1000 Lithons** ;
- achat unique et permanent ;
- droit attaché au compte et réutilisable avec un futur caillou adopté ;
- prix, solde et propriété jamais décidés par le navigateur ;
- débit du wallet, ledger et entitlement dans une transaction côté Supabase ;
- idempotence par `event_key` ;
- second achat distinct refusé.

### 3.2 Modèle générique de fonctionnalités payantes

10.5 n'a pas ajouté un simple booléen spécifique dans le profil.

Le backend utilise un catalogue de fonctionnalités et une table de déblocages utilisateur :

```text
feature_catalog
user_feature_unlocks
```

L'entrée initiale est `rock_movement` à 1000 Lithons.

Le ledger Lithon accepte le motif `feature_unlock` et référence la fonctionnalité concernée.

## 4. Manutention tactile du caillou

### 4.1 Six degrés de liberté

Une fois le permis acquis, le caillou peut être manipulé sans changement d'échelle :

- translation X ;
- translation Y ;
- translation Z ;
- rotation X ;
- rotation Y ;
- rotation Z.

La scène applique une enveloppe de sécurité pour éviter qu'un caillou soit envoyé hors de portée ou sous le monde.

### 4.2 Sous-modes tactiles

Le contrôle est séparé en deux sous-modes :

#### Position

- un doigt : déplacement dans le plan de vue ;
- geste à deux doigts : déplacement en profondeur.

#### Orientation

- un doigt : rotation libre de type trackball ;
- twist à deux doigts : rotation complémentaire autour de l'axe de vue.

Le but reste une manipulation 3D directe plutôt qu'une exposition de six sliders techniques.

### 4.3 Modes exclusifs

Les grands états du Socle sont désormais mutuellement exclusifs :

- observation / orbit ;
- caresse ;
- nettoyage ;
- édition accessoire ;
- manutention position ;
- manutention orientation ;
- stabilisation globale.

La boutique peut s'ouvrir depuis le flux accessoire sans rendre la scène éditable accidentellement.

## 5. Physique globale après manutention

### 5.1 Pendant le geste

Pendant la manutention :

- le caillou est cinématique ;
- les accessoires suivent la composition et restent gelés ;
- la gravité ne perturbe pas le geste ;
- aucune nouvelle vérité canonique n'est persistée avant validation.

### 5.2 À la validation

Après validation :

- le corps physique du caillou est recréé / activé comme corps dynamique ;
- les accessoires concernés sont libérés dans le même cycle de stabilisation globale ;
- la gravité agit sur le caillou et les accessoires ;
- les collisions caillou / sol, accessoire / sol, accessoire / caillou et accessoire / accessoire restent actives ;
- le caillou peut tomber, rouler, basculer ou se retourner ;
- les accessoires peuvent glisser, tomber et finir sur le grand carré.

Une correction spécifique apportée pendant la validation garantit que le corps Rapier n'est pas conservé dans son ancien état fixe au passage vers la simulation globale.

### 5.3 Collider dynamique du caillou

Le caillou dynamique utilise un collider `hull`, adapté aux corps dynamiques Rapier, à partir du modèle chargé.

Le mesh visuel reste inchangé. Le collider physique est indépendant du rendu.

Cette solution fonctionne sur les 20 spécimens du catalogue sans ajouter vingt assets physiques manuels distincts.

## 6. Persistance de la composition

### 6.1 Pose persistante du caillou

`user_rocks` stocke désormais une pose physique persistante comprenant :

- position `[x, y, z]` ;
- rotation quaternion `[x, y, z, w]` ;
- timestamp de stabilisation.

La pose est hydratée avec le caillou actif et devient la référence du Socle après reload.

### 6.2 Accessoires conservés dans le repère local du caillou

Le contrat historique de 10C / 10D est conservé : les accessoires restent persistés dans le **repère local du caillou**.

10.5 introduit explicitement les conversions :

```text
local accessoire -> monde via pose du caillou
monde final -> local via inverse de la pose finale du caillou
```

Après une stabilisation globale :

1. Rapier fournit la pose monde finale du caillou ;
2. Rapier fournit la pose monde finale de chaque accessoire ;
3. chaque transform accessoire est reconverti dans le nouveau repère local du caillou ;
4. la composition finale est persistée atomiquement.

### 6.3 Stabilisation atomique et idempotente

Supabase expose la mutation transactionnelle :

```text
stabilize_rock_composition(..., event_key)
```

Elle enregistre dans une seule transaction :

- pose finale du caillou ;
- date de stabilisation du caillou ;
- transforms locaux finaux des accessoires ;
- dates de stabilisation accessoires ;
- reçu d'idempotence.

Une erreur sur une partie de la composition provoque un rollback complet.

Les mises à jour directes de pose depuis un rôle navigateur authentifié restent interdites.

## 10. Défauts découverts et corrigés pendant la validation

La validation finale a volontairement fait remonter plusieurs défauts qui ont été corrigés avant clôture :

### 10.1 Lint / TypeScript strict

- deux lint initiaux ;
- accès tuple / array considérés comme potentiellement `undefined` sous le niveau TypeScript utilisé ;
- compatibilité `exactOptionalPropertyTypes` pour les callbacks Rapier.

Tous sont corrigés et le pipeline général est vert.

### 10.2 Cycle Rapier du caillou

La première version pouvait conserver un corps dans un état incompatible lors de la transition fixe / cinématique / dynamique.

Le cycle a été corrigé pour que la libération globale utilise bien un corps dynamique effectif.

### 10.3 Fixture WebGL 10.5

La fixture de validation recréait initialement certains callbacks de chargement à chaque render, provoquant des reloads du GLB et pouvant mettre la physique en pause dans le banc de test.

La fixture a été stabilisée sans réduire les critères métier.

### 10.4 Cibles tactiles du Réglage fin

Les anciens tests comptaient les boutons cachés d'un `<details>` fermé comme des cibles tactiles de 0 px.

Les contrôles ont été corrigés pour :

- ouvrir explicitement `Réglage fin` avant interaction ;
- vérifier les 44 px uniquement sur les cibles réellement visibles ;
- conserver toutes les assertions de transform et de persistance.

### 10.5 Contrat `ActiveRock`

Les fixtures historiques adoption / caresse / nettoyage ne fournissaient pas les nouvelles propriétés de pose 10.5.

Elles ont été mises à jour pour représenter un `ActiveRock` canonique avec pose neutre et stabilisation cohérente.

Les parcours historiques sont de nouveau verts.
